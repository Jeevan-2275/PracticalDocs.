📝 General Exam Instructions & Best Practices
When attempting these practical exam questions, keep the following guidelines in mind:

For Coding Tasks (Java, C, etc.)
Readability: Ensure your code is clean, well-indented, and uses meaningful variable names.
Error Handling: Always include proper exception handling (e.g., try-catch blocks in JDBC) to demonstrate robustness.
Comments: Briefly comment complex logic to explain why you are doing something, not just what you are doing.
For System Design Tasks (Cloud & DevOps)
Address Constraints: Always explicitly address the constraints provided in the scenario (e.g., Cost, Latency, High Concurrency).
Justify Choices: Explain why you chose a specific technology. (e.g., "I chose WebSockets over HTTP polling because the scenario requires ultra-low latency").
Think About Failure: Always include a section on Fault Tolerance or what happens when a component goes down (e.g., Multi-AZ deployments, hardware fallbacks).
🎯 Evaluation Criteria
Examiners typically grade practical submissions based on:

Correctness: Does the code run? Does the architecture solve the core problem?
Optimization: Is the solution efficient in terms of time/space complexity or cloud infrastructure costs?
Security: Are credentials handled safely? Is the environment isolated?
Clarity: Is the final output easy to read and understand?
